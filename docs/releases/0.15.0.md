# 0.15.0 release candidate

Prepared on 2026-11-01 (Europe/Berlin) on `dev`. The candidate fixes the findings of the
2026-10-31 UX test: a reworked saved-prompt header (one Edit | Fill and copy switch, Refine and
Evaluate as buttons, a More menu), one vocabulary for variables, values and placeholders, and
accessibility, library, evaluation, editor, sign-in and public-page fixes. It also raises the
reverse proxy's write timeout so long evaluation runs are not cut off. All six version
declarations report `0.15.0`. The tag, image publication, production deployment and MCP Registry
publication have not happened yet.

## Changes and upgrade

The [changelog](../../CHANGELOG.md) lists every change. The new header layout is recorded in the
[decision log](../../product/DECISIONS.md); the deferred follow-ups are in the
[backlog](../../product/BACKLOG.md).

**API:** no route, request or response schema changes. `POST /api/prompts/{id}/duplicate` names
the copy "Name (copy)", then "Name (copy 2)", instead of "Name Duplicate". See
[API reference](../api.md).

**Database:** no migrations.

**Configuration:** the `Caddyfile` write timeout is `15m` (was `30s`), so HTTP/1.1 and HTTP/2
clients receive evaluation runs that take longer than 30 seconds. Production has run with this
value and `LLM_TIMEOUT_SECONDS=180` since 2026-10-30. Caddy mounts the `Caddyfile` as a single
read-only file, so a changed file needs a restart of the Caddy container, not only
`caddy reload`. No new settings, and no Compose or MCP tool changes. Upgrade by deploying the
matching backend and frontend images; image publication does not deploy the app.

**Dependencies:** no changes.

## Validation

On 2026-11-02 (Europe/Berlin), `COMPOSE_DISABLE_ENV_FILE=1 make ci-local` passed on
the candidate (exit 0), without loading the operator's root `.env`:

- 1,065 backend tests passed with 97.16% coverage, above the 90% gate.
- 657 frontend tests across 51 files passed with coverage thresholds met.
- All 95 browser tests passed against an isolated Compose stack, including the accessibility
  audit in dark and light theme.
- Secret scans, dependency locks, lint/types, backend and production frontend
  security checks (including `pip-audit`), production builds, monitoring, Docker smoke
  tests and third-party notices passed. The production `npm audit` found no vulnerabilities;
  the 16 moderate findings are in development-only ESLint dependencies.
- Neither application image has fixable HIGH/CRITICAL vulnerability findings.

Local CI does not run GitHub CodeQL, publish images or deploy the application.
