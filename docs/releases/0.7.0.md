## Changes and upgrade

- A public `/terms` page reads the operator's `nutzungsbedingungen.html` from the
  runtime legal directory, without requiring sign-in.
- The shared legal links on the homepage, sign-in screen, app footer and legal
  pages include Terms of Service when the file is present. Existing legal URLs
  remain unchanged.
- The page reads the file on each request, so content edits take effect without
  rebuilding. A missing file or unconfigured directory returns 404 and omits the
  link. Operator HTML is trusted in the same way as the existing legal pages.
- The operator supplies and deploys the terms separately. Mount the legal folder
  and make `nutzungsbedingungen.html` readable by the frontend container's
  non-root user. See [deployment documentation](../deployment.md).
- No database migrations, dependency changes or REST/MCP tool schema changes.
  `/legal.json` can now also report `nutzungsbedingungen` as an available page;
  its navigation URL is `/terms`.
- This release serves the document; it does not implement terms acceptance,
  acceptance-version records or an existing-user agreement flow.
- Deploy the new frontend image before expecting `/terms` to work. Copying the
  HTML alone does not add the route. Image publication does not deploy the app.
- The backend image has synchronized version metadata and remains behaviorally
  unchanged. Keep the application image pair on matching release versions.
