## What this changes

The optional monitoring profile gains App Overview, AI & Evaluation and API
Health dashboards, provisioned alerts and Prometheus rules. Structured JSON logs
connect requests, operations, safe failures and migration progress. Telemetry
distinguishes committed business operations, provider attempts and evaluation
case outcomes; it is not an audit ledger or a billing invoice.

The release also addresses the verified review findings: immutable account token
identities, bcrypt byte limits, public provider DNS/IP enforcement, spend retained
after AI failures, evaluation transaction timing, paged history, pricing refresh
contention, private atomic backups and WAL-safe restores. Frontend fixes cover
session-check recovery, readable validation, save/history failures, independent
evaluation loading, mobile navigation focus and inline section limits.

The verified pentest findings are addressed: provider defaults follow the same
private-address policy as explicit URLs; OAuth client revocation invalidates
existing access tokens and pending credentials; and codes approved before global
sign-out or a password change/reset cannot restore access. Refresh exchanges
recheck revocation within their write transaction, JWTs retain the validated
version across commit, and overlapping account revocations increment atomically.
Delayed client revocations cannot disconnect a replacement account or a newly
reauthorized connection.
The documented inline-script CSP limitation remains a hardening item, with no
XSS demonstrated by the assessment.

Account security and session handling also change. Keyboard and pointer
activity renews browser sessions, capped 12 hours after the last password entry.
Users can sign in with their username or email. New passwords need 10+
characters, a number and a special character. Changing the recovery email
requires the current password and notifies the previous address.
Sign-out waits for pending refreshes before clearing cookies, preventing a late
response from restoring the session. Renewal also adapts to short session lifetimes.

Three public practical guides cover reusable prompts, template variables and
organizing ChatGPT prompts, with worked examples, related articles and app links.

Release publication scans an untagged image by immutable digest before promoting
that same index, including provenance and SBOMs, to release tags. SQLite helper
and Trivy images are pinned, and monitoring validation runs in CI.

Type of change: Feature · Security fix · Bug fix · Compatibility change · Docs.
The complete list is in the [0.5.0 changelog](../../CHANGELOG.md).

## Upgrade and compatibility

- Follow [Upgrading to 0.5.0](../deployment.md#upgrading-to-050). Back up and
  rehearse the forward-only migration on an isolated production-backup copy.
- Startup migration `026_user_auth_subject` assigns account UUIDs. Existing
  username-subject sessions stop authenticating: sign in again. Migration
  `027_oauth_grants` clears legacy pending codes and refresh tokens; existing
  OAuth access tokens lack grant versions and are rejected. Reauthorize MCP
  clients using their existing registrations. Passwords over 72 UTF-8 bytes
  need a reset.
- User-configured Ollama/vLLM private endpoints now require explicit private-URL
  opt-in, like custom endpoints. An operator-managed server default remains the
  trusted local-provider alternative. Public-only connections disable redirects
  and environment proxies and pin each request to validated public DNS answers.
- The provider SDK now uses HTTPX2 and system CA certificates. Install custom
  provider CAs in the operating-system trust store rather than modifying a
  `certifi` bundle. TLS verification remains enabled.
- Update Compose, scripts and monitoring provisioning together, including the
  new Grafana entrypoint script and a non-placeholder admin password. Update
  custom log parsers and queries for JSON events and `pms_*` application metrics.
  See [monitoring](../monitoring.md) for exact labels, alerts and limitations.
- Evaluation history defaults to 50 runs, with `limit` capped at 100 and
  nonnegative `offset`. Clients needing the full history must page it.
- Backup archives use mode `0600`. Restore runs as `1000:1000`; if the archive's
  owner differs, grant that account read access before restoring. Stop other
  SQLite users; a failed Make restore leaves services stopped for inspection.
- Migration 020 now allows the 025 note backfill on upgrades crossing both
  steps. It does not guess repairs for previously damaged note history; compare
  affected records with a verified backup. Earlier recovery requirements remain
  in the [0.3.0 record](0.3.0.md#upgrade-and-compatibility).
- The stricter password policy applies only when a password is set; existing
  passwords keep working. API clients changing the email through
  `PATCH /api/auth/me` must send `current_password`.

## Validation record

`make ci-local` passed on the `0.5.0` candidate with the pentest fixes, public
guides and session-renewal fixes on 2026-10-15 (exit 0): 937 backend tests with
97.06% coverage, 303 frontend tests across 34 files and 33 browser tests.
The 24 new OAuth security regressions cover client
isolation, reauthorization, stale codes after sign-out/password changes/resets,
concurrent exchanges, atomic revocation counters, signing across commit, legacy
tokens, and delayed revocation across reauthorization or account ID reuse. The
reported vulnerabilities and additional races were reproduced before fixing
them; independent review found no remaining issues in the changed security paths.
The new tests also pass after the database-configuration module reload exercised
by the full suite. Migration upgrade/idempotency and backup/restore checks pass.
Six frontend regressions cover pending refresh success and failure, rotated CSRF
headers, blocked renewal during sign-out, login ordering and short session
lifetimes. A browser regression verifies that a delayed refresh cannot restore
the session cookie after sign-out and that signing in again restores saved work.

The light-theme refinement contrast check passes without relaxing accessibility
assertions. The earlier focused SDK/egress/billing/logging suite passed all 109
tests; the HTTPX2 transport regression was reproduced before that fix.

All six version declarations agree. Runtime checks confirmed `0.5.0` in the
published backend image's FastAPI metadata and the frontend package,
OpenAI SDK 3.13.0 with the protected HTTPX2 transport and system CA roots in the
backend image, and Next.js 16.4.1 in the frontend image. Local documentation
links and heading anchors resolve.

Local CI covers secret and lock checks, lint/types, dependency security, builds,
frontend/backend coverage, isolated browser workflows, Compose, Prometheus
semantic tests, non-root backup/restore, Docker smoke/image scans and license
notices. It does not publish images, run GitHub CodeQL or exercise a live provider
or a production backup. The real operator environment file is not needed.

The informational full frontend dependency audit still reports five high-severity
