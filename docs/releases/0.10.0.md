## Changes and upgrade

The [changelog](../../CHANGELOG.md) lists every change. In short:

- **Free tools without an account.** `/tools` has a template filler, a prompt checker,
  a word-level diff and a token counter with estimated costs; nothing is uploaded. Four
  new guides and a gallery of 24 templates at `/gallery` can be filled in, copied or
  saved to the library after signing in.
- **A free refiner, off by default.** `/tools/prompt-refiner` lets signed-out visitors
  refine a pasted prompt on the operator's server-default connection, within
  per-visitor, daily and monthly limits.
- **Inputs with choices.** An input can list choices, one per line; Fill mode offers
  them as a list (for example an art style or a character).
- **Re-import that keeps your work.** Updating a changed note keeps the inputs made on
  the first import; prompts that share a title are no longer overwritten by mistake;
  note templates and link-only pages start unticked; Notion page links read as text.
- **Editor and library polish.** History is an accessible dialog on narrow screens,
  Insert input accepts names such as `max rows!`, plain not-found and email messages,
  a sticky bulk action bar, the search kept in the address, an Unsaved draft marker,
  and a 10-second Undo after deleting.
- **Theme and spelling.** Public pages follow the system's light or dark setting until
  a theme is chosen; the app uses British spelling (Favourites).

API changes, all backward compatible:

- New unauthenticated endpoints under `/api/public`: `GET /model-prices`,
  `GET /refine`, `POST /refine/questions` and `POST /refine/draft`. `GET /refine`
  reports whether the refiner is offered; the two `POST` endpoints return 404 unless
  `PUBLIC_REFINE_ENABLED=true`.
- Variable metadata accepts optional `options` (up to 50 strings of up to 200
  characters, tidied by the server, omitted when unset). Prompt responses, versions,
  the data export and the MCP `get_prompt` tool return it; MCP tool names and inputs
  are unchanged.
- Validation errors use plainer messages for email addresses and drop pydantic's
  "Value error, " prefix.

See [API reference](../api.md).

**Database:** one forward-only migration runs at startup: `033_public_billed_calls`
adds the free refiner's spend ledger table. Back up the database before upgrading, as
[deployment](../deployment.md) describes.

**Configuration:**

- **Registration is open by default.** A deployment that relied on the implicit closed
  default must set `REGISTRATION_MODE=closed`; any unrecognised value is also treated
  as closed.
- **Free refiner settings** (all optional; Compose and `.env.example` carry the
  defaults): `PUBLIC_REFINE_ENABLED` (default `false`), `PUBLIC_REFINE_RATE_LIMIT`
  (`6/minute;30/day` per visitor IP), `PUBLIC_REFINE_DAILY_LIMIT` (200 calls a UTC
  day), `PUBLIC_REFINE_MAX_OUTPUT_TOKENS` (8000), `PUBLIC_REFINE_MODEL` and
  `PUBLIC_MONTHLY_BUDGET_USD`. Before enabling the refiner, mention it in the privacy
  policy (pasted text goes to the server-default provider; visitor IPs are held in
  memory for rate limiting), confirm the backend sees real client IPs, and set the
  limits and budget. Its admission lock assumes one backend process.
- The only runtime dependency change is `opentelemetry-api` 1.45.1 for CVE-2026-114603.
  The development lock also moves `filelock` to 4.2.4 and `setuptools` to 84.2.1 for
  advisories `pip-audit` first reported on 2026-10-24; neither package is in the
  application images.

No Caddy or MCP tool-name changes. Upgrade by deploying the matching backend and
frontend images; image publication does not deploy the app.

## Validation

On 2026-10-23 (Europe/Berlin), `COMPOSE_DISABLE_ENV_FILE=1 make ci-local` passed on
the candidate (exit 0), without loading the operator's root `.env`:

- 1,060 backend tests passed with 97.15% coverage, above the 90% gate.
- 582 frontend tests across 46 files passed with coverage thresholds met.
- All 93 browser tests passed against an isolated Compose stack.
- Secret scans, dependency locks, lint/types, backend and production frontend
  security checks (including `pip-audit` after the `opentelemetry-api` update),
  production builds, monitoring, Docker smoke tests and third-party notices passed.
- Neither application image has fixable HIGH/CRITICAL vulnerability findings.

That run reported an unused lint directive in `useLibrary.ts`; it was removed as a
comment-only change, after which lint and the library tests were rerun clean. Lint
still reports one warning in unchanged `src/app/error.tsx`. Every merged change also
passed `make ci-local` or its affected stages before it reached `dev`.

The CI stack starts from a fresh database, so migration 033 has not been exercised
against an existing database in this run. AI features were tested with mocked
providers; the free refiner has not been run against a live model. Three open
Dependabot alerts concern `vite`, which is only a frontend development and test
dependency and is not in the production image. Local CI does not run GitHub CodeQL,
publish images or deploy the application.

[`main` pipeline](https://github.com/chrysogonus/prompt-maker-studio/actions/runs/40091657124)
and [tag pipeline](https://github.com/chrysogonus/prompt-maker-studio/actions/runs/40094262126)
then passed all quality gates, including CodeQL. Both publish jobs promoted the scanned
image indexes to release tags.

Registry verification confirmed that `0.10.0`, `0.10` and `sha-80097b2` resolve to the
matching digest for each image. OCI labels identify version `0.10.0` and the tagged
