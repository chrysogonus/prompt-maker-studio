# 0.17.1 release record

Published on 2026-11-17 (Europe/Berlin):
[GitHub release](https://github.com/chrysogonus/prompt-maker-studio/releases/tag/v0.17.1).
Tag `v0.17.1` points to `77e74e6daa87cf8cfd71c3ff5425413a8de15561`.
[Release PR #111](https://github.com/chrysogonus/prompt-maker-studio/pull/111) was merged into
`main` with a merge commit after all quality gates passed; the tagged commit has the same tree as
`dev` at `1f5a1f0`. A security patch: the frontend image moves to a `node:22-alpine` base with
`zlib` 1.3.2-r1, which fixes CVE-2026-85091 (HIGH) in the 0.17.0 frontend image. The same base
ships OpenSSL 3.5.9, so the `apk upgrade` workaround for CVE-2026-14456 is gone. The backend image
has the same `zlib` CVE; no `python:3.12-slim` digest ships Debian's fix yet, so
`backend/Dockerfile` upgrades `zlib1g` explicitly. The backend updates `opentelemetry-api` to
1.45.2 for CVE-2026-126360, a ReDoS in trace-context extraction that the MCP SDK runs on each MCP
request's `_meta`, and `dnspython` to 2.9.2 for CVE-2026-128089. The frontend updates `next` to
16.4.5 for GHSA-mfr8-8qww-v76h, which the app is not affected by but which failed the production
audit gate. A development-only dependency, `minimatch`, moves to 11.0.4. All six version
declarations report `0.17.1`. Production was deployed on 2026-11-17, and `server.json` 0.17.1 was
published to the MCP Registry at 00:16 UTC, where it is active and latest.

## Changes and upgrade

The [changelog](../../CHANGELOG.md) lists every change.

**API:** no REST route, request or response schema changes, and no MCP changes.

**Database:** no migrations.

**Configuration:** no new settings, and no Compose or `Caddyfile` changes. Upgrade by deploying
the matching backend and frontend images; image publication does not deploy the app.

**Dependencies:** in the backend locks, `opentelemetry-api` 1.45.1 → 1.45.2 (via `fastapi` and
`mcp`) and `dnspython` 2.9.0 → 2.9.2 (via `email-validator`); nothing else changes. Both were
found by `pip-audit` while validating the candidate. In the frontend, `next` and
`eslint-config-next` move from 16.4.2 to 16.4.5 (with `@next/env`, `@next/eslint-plugin-next` and
the `@next/swc-*` binaries); the production `npm audit` flagged `next` during the same
validation. The backend image upgrades `zlib1g` from `1:1.3.dfsg+really1.3.1-1+b1` to
`1:1.3.dfsg+really1.3.1-1+deb13u1` on the unchanged `python:3.12-slim` base (`sha256:e695ab18…`);
the newest upstream digest, `sha256:5e2bdb1b…` (2026-11-05), still ships the vulnerable build.
The `db-backup` service runs that base directly and keeps the old `zlib1g`; it only compresses
the app's own database through Python's `gzip` module, which does not use the affected
`gzFile` code. The frontend base image digest changes to
`node:22-alpine@sha256:0e1754758c2df4cfa3e68d59e2e1b7374bb7fd9ea6328eaaacf15cc934af8202`. The
`minimatch` override rises from `>=10.2.5` to `>=11.0.1` (locked at 11.0.4), which closes
Dependabot alert #42. `minimatch` is a development-only dependency and is not in the production
image.

## Validation

On 2026-11-17 (Europe/Berlin), `COMPOSE_DISABLE_ENV_FILE=1 make ci-local` passed on
the candidate (exit 0), without loading the operator's root `.env`:

- 1,069 backend tests passed with 97.17% coverage, above the 90% gate.
- 657 frontend tests across 51 files passed with coverage thresholds met.
- All 95 browser tests passed against an isolated Compose stack.
- Secret scans, dependency locks, lint/types, backend and production frontend
  security checks (including `pip-audit`), production builds, monitoring, backup ownership,
  Docker smoke tests and third-party notices passed. `npm audit` found no vulnerabilities in
  the full tree.
- Neither application image has fixable HIGH/CRITICAL vulnerability findings.

Earlier runs on the candidate failed, in turn, on `pip-audit` (`opentelemetry-api`,
`dnspython`), the production `npm audit` (`next`) and the backend image scan (`zlib1g`); each
fix above followed one of those failures.

Local CI does not run GitHub CodeQL, publish images or deploy the application.

No application changes followed the recorded local run; only these release notes changed. These
runs passed all quality gates, including CodeQL:

Both publish jobs promoted the scanned image indexes to release tags.

## Deployment

Deployed to production on 2026-11-17 at about 00:07 UTC. The database was backed up first
(integrity check passed). Both containers run the digests above. The `Caddyfile` and the
`db-backup` digest are unchanged, so Caddy and the backup worker were not restarted, and Caddy
logged no 5xx responses during the backend restart. Smoke checks passed: app version 0.17.1,
`zlib1g` `1:1.3.dfsg+really1.3.1-1+deb13u1`, `opentelemetry-api` 1.45.2 and `dnspython` 2.9.2 in
the backend, `zlib` 1.3.2-r1 and `next` 16.4.5 in the frontend, the public pages and sitemap,
OAuth discovery, the MCP endpoint's 401 challenge and the legal pages, with no error logs.
