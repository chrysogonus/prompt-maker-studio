# 0.17.0 release candidate

Prepared on 2026-11-04 (Europe/Berlin) on `dev`. A new optional setting, `LLM_WORKSPACE_ID`,
sets the Anthropic workspace for the server-default connection, as users already can for their
own connection in Settings. Anthropic requires the `anthropic-workspace-id` header on every
request made with a key that is not scoped to one workspace. The backend and backup images move
to a `python:3.12-slim` base with `apt` 3.0.4, which fixes CVE-2026-109518. All six version
declarations report `0.17.0`. Image publication, production deployment and MCP Registry
publication have not happened yet.

## Changes and upgrade

The [changelog](../../CHANGELOG.md) lists every change.

**API:** no REST route, request or response schema changes, and no MCP changes.

**Database:** no migrations.

**Configuration:** new optional `LLM_WORKSPACE_ID` (`wrkspc_...`), passed to the backend by
`docker-compose.yml`. It is sent only when `LLM_PROVIDER=anthropic` and the base URL's host is
`api.anthropic.com`, with redirects disabled. Leave it empty for workspace-scoped keys and other
providers. No `Caddyfile` changes. Upgrade by checking out the tag, so the new Compose file is
used, and deploying the matching backend and frontend images; image publication does not deploy
the app.

**Dependencies:** the `python:3.12-slim` base moves to digest `sha256:e695ab18…`, with `apt` 3.0.4
and Python 3.12.16. It already includes the `libpcre2-8-0` fix, so the backend image no longer
upgrades that package itself. No application dependency changes.

## Validation

On 2026-11-05 (Europe/Berlin), `COMPOSE_DISABLE_ENV_FILE=1 make ci-local` passed on
the candidate (exit 0), without loading the operator's root `.env`:

- 1,069 backend tests passed with 97.17% coverage, above the 90% gate.
- 657 frontend tests across 51 files passed with coverage thresholds met.
- All 95 browser tests passed against an isolated Compose stack.
- Secret scans, dependency locks, lint/types, backend and production frontend
  security checks (including `pip-audit`), production builds, monitoring, backup ownership,
  Docker smoke tests and third-party notices passed. The production `npm audit` found no
  vulnerabilities; the 8 moderate findings are in development-only dependencies.
- Neither application image has fixable HIGH/CRITICAL vulnerability findings.

Local CI does not run GitHub CodeQL, publish images or deploy the application.
