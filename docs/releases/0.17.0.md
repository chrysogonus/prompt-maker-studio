# 0.17.0 release record

Published on 2026-11-05 (Europe/Berlin):
[GitHub release](https://github.com/chrysogonus/prompt-maker-studio/releases/tag/v0.17.0).
Tag `v0.17.0` points to `bb46eaac9853610ae1bcf473eca91fa080b68323`.
[Release PR #104](https://github.com/chrysogonus/prompt-maker-studio/pull/104) and the fix
[PR #106](https://github.com/chrysogonus/prompt-maker-studio/pull/106) were merged into `main`
with merge commits; the tagged commit has the same tree as `dev` at `13dc894`. A new optional
setting, `LLM_WORKSPACE_ID`, sets the Anthropic workspace for the server-default connection, as
users already can for their own connection in Settings. Anthropic requires the
`anthropic-workspace-id` header on every request made with a key that is not scoped to one workspace. The backend and backup images move
to a `python:3.12-slim` base with `apt` 3.0.4, which fixes CVE-2026-109518. All six version
declarations report `0.17.0`. Production was deployed on 2026-11-05, and `server.json`
0.17.0 was published to the MCP Registry at 17:39 UTC, where it is active and latest.

The `v0.17.0` tag first pointed to `c122815`, the merge of #104. That pipeline failed the backend
image scan on CVE-2026-109518, shortly after the same tree had passed the scan on the release
PR, and published nothing. The tag was moved to the merge of #106, which contains the fix.

## Changes and upgrade

The [changelog](../../CHANGELOG.md) lists every change.

**API:** no REST route, request or response schema changes, and no MCP changes.

**Database:** no migrations.

**Configuration:** new optional `LLM_WORKSPACE_ID` (`wrkspc_...`), passed to the backend by
`docker-compose.yml`. It is sent only when `LLM_PROVIDER=anthropic` and the base URL's host is
`api.anthropic.com`, with redirects disabled. Leave it empty for workspace-scoped keys and other
providers. No `Caddyfile` changes. Upgrade by checking out the tag, so the new Compose file is
used, and deploying the matching backend and frontend images; image publication does not deploy
the app. If you run the scheduled backup worker, recreate it too (`--profile backup up -d
--no-build --no-deps db-backup`), because its image digest changes.

**Dependencies:** the `python:3.12-slim` base moves to digest `sha256:e695ab18…`, with `apt` 3.0.4
and Python 3.12.16. It already includes the `libpcre2-8-0` fix, so the backend image no longer
upgrades that package itself. No application dependency changes.

## Deployment

Deployed to production on 2026-11-05 at about 15:43 UTC. The database was backed up first
(integrity check passed). Both containers run the digests above, and the scheduled backup
worker was recreated on the new base image, because deploying only the backend and frontend
does not recreate it. The `Caddyfile` is unchanged, so Caddy was not restarted. Two
`POST /api/mcp` requests received a 502 during the backend restart.

Smoke checks passed: app version 0.17.0, `apt` 3.0.4 in the backend and backup worker, all 46
sitemap URLs including the legal pages, OAuth discovery and the MCP endpoint's 401 challenge,
with no backend error logs. Signed-in sessions, MCP tool calls and a request using
`LLM_WORKSPACE_ID` were not exercised on production.
