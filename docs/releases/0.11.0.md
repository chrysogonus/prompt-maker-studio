Published on 2026-10-27 (Europe/Berlin):
[GitHub release](https://github.com/chrysogonus/prompt-maker-studio/releases/tag/v0.11.0).

## Changes and upgrade

The [changelog](../../CHANGELOG.md) lists every change. In short:

- **AI answers as Markdown.** Test with AI and Evaluate render tables, lists, headings
  and emphasis, with a Plain text button for the exact text. Raw HTML is not rendered,
  images show as their alt text and links open in a new tab.
- **Safer editing.** The filled preview no longer breaks on inputs named `__proto__` or
  `constructor`, and a save conflict offers Compare, Keep my edits and Use the saved
  version.
- **Clearer sign-up and account actions.** Username rules are stated and checked before
  submitting, Sign out everywhere asks first, and the sign-in page links home.
- **Library search.** An empty search in a folder offers Search all prompts, and
  excerpts keep words and `{{variables}}` whole.
- **Design audit fixes.** Readable placeholders in dark mode, 44px touch targets,
  consistent focus rings, no coloured side stripes, and reduced-motion spinners that
  still show progress.
- **Self-hosted connections.** Settings suggests a local Ollama or vLLM address only
  when the server allows private addresses, and otherwise explains why not.

API changes, all backward compatible:

- The LLM connection response (`GET /api/auth/me/llm-connection`) adds
  `private_urls_allowed`, which reflects `ALLOW_PRIVATE_LLM_URLS`.
- The message for a refused private base URL is reworded for users of a hosted
  instance; it still names `ALLOW_PRIVATE_LLM_URLS=true` for self-hosters.

See [API reference](../api.md).

**Database:** no migrations.

**Configuration:** no new or changed settings, and no Compose, Caddy or MCP tool
changes. Upgrade by deploying the matching backend and frontend images; image
publication does not deploy the app.

**Dependencies:**

- Backend runtime: `fastapi` 0.146.0, `starlette` 1.9.0, `pydantic` 2.14.1
  (`pydantic-core` 2.50.1), `openai` 3.35.1, `sqlalchemy` 2.1.5, `httpx2` and
  `httpcore2` 2.14.0, and `typing-inspection` 0.4.4. None of these is a security fix.
- Backend security: `dnspython` 2.9.0 for CVE-2026-114605, which `pip-audit` first
  reported on 2026-10-27 and which failed the `main` pipeline after release PR #74
  merged. It comes in through `email-validator`, which the app uses without DNS
  lookups, so the affected parser is not expected to be reached.
- Frontend runtime: `react-markdown` 10 and `remark-gfm` 4 are new, for rendering AI
  answers; the [third-party notices](../../THIRD_PARTY_NOTICES.md) list them and their
  dependencies. See the decision log for why raw HTML stays off.
- Development only: `vite` 8.3.5 and `vitest`/`@vitest/coverage-v8` 4.1.12 resolve the
  seven open Dependabot alerts for `vite` (GHSA-587h-7wmj-h5pm and four others) and
  `@vitest/mocker` (GHSA-qxg6-89mg-rqv8, GHSA-xp26-3454-mjgp). Neither package is in
  the application images, and the alerts close when this release reaches `main`.
  `ruff` 0.17.1 and Dependabot now hold the React package majors together.

## Validation

On 2026-10-26 (Europe/Berlin), `COMPOSE_DISABLE_ENV_FILE=1 make ci-local` passed on
the candidate (exit 0), without loading the operator's root `.env`:

- 1,063 backend tests passed with 97.15% coverage, above the 90% gate.
- 612 frontend tests across 48 files passed with coverage thresholds met.
- All 93 browser tests passed against an isolated Compose stack.
- Secret scans, dependency locks, lint/types, backend and production frontend
  security checks (including `pip-audit`), production builds, monitoring, Docker smoke
  tests and third-party notices passed.
- Neither application image has fixable HIGH/CRITICAL vulnerability findings.

Before the run, the browser suite's two-tab conflict test was updated (`d611362`) to
check the removed and added words of the merged word diff; the app's behaviour was
unchanged. An earlier full run on the UI/UX fixes passed every stage except the
browser tests, which stalled because headless Chromium on the build machine stopped
rendering; this run is the first full browser pass for those changes.

AI features were tested with mocked providers; Markdown rendering has not been checked
against a live model's answers. Local CI does not run GitHub CodeQL, publish images or
deploy the application.

## Publication verification

One commit followed the recorded local run. After #74 merged, the `main` pipeline failed
`pip-audit` on CVE-2026-114605 for `dnspython` 2.8.0, first reported on 2026-10-27.
`625d795` moved it to 2.9.0 in both locks and updated the notices. Unlike the 0.10.0
follow-up, the package is in the backend image; it comes in through `email-validator`,
which the app uses without DNS lookups. The `ci-local` stages passed again with the same
test counts and coverage. One browser test (`editor-layout.spec.ts`, 1280px light)
failed on the first run because the page was measured before its styles loaded; it
passed on a full rerun of the browser suite, and the stages after it were then run in
order. The
[#80 pipeline](https://github.com/chrysogonus/prompt-maker-studio/pull/80/checks),
[`main` pipeline](https://github.com/chrysogonus/prompt-maker-studio/actions/runs/40550027113)
and [tag pipeline](https://github.com/chrysogonus/prompt-maker-studio/actions/runs/40552671935)
then passed all quality gates, including CodeQL. Both publish jobs promoted the scanned
image indexes to release tags.

Registry verification confirmed that `0.11.0`, `0.11` and `sha-8b87293` resolve to the
matching digest for each image. OCI labels identify version `0.11.0` and the tagged
revision. Both indexes retain SLSA provenance and SPDX SBOMs.

The maintainer approved both merges with the established administrator merge exception
after all quality checks passed, preserving `dev` ancestry. No protection settings were
changed and no quality check was bypassed. At publication, no Dependabot alerts are open.
