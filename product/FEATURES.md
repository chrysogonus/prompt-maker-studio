| Route protection | ✅ Implemented | httpOnly session cookie (CSRF-protected on writes) or HTTP Bearer token protects prompt data endpoints, including the per-user `GET /api/prompts/config` capability check and all provider-connection endpoints | `backend/app/auth/dependencies.py`, `backend/app/api/routes.py`, `backend/app/api/auth_routes.py` |
| Username normalization | ✅ Implemented | Usernames lowercased on register and login to prevent duplicate account variants | `backend/app/api/auth_routes.py` |
| Frontend auth flow | ✅ Implemented | Register/login/forgot-password form with auto-login after registration; the session token is delivered in an httpOnly cookie the page cannot read, with double-submit CSRF on writes (only the expiry timestamp is stored client-side). A 401 records the expired-session reason and return path, shows an inactivity message instead of failing silently, and preserves prompt/refinement drafts for recovery after login. Near-expiry tokens also produce an in-app warning. Reload-time network/5xx failures preserve the durable token and offer a session-check retry instead of falsely logging the user out. Forms are client-validated (`noValidate` with inline `role="alert"` messages) rather than relying on native browser tooltips — whitespace-only username/password is rejected, usernames are trimmed before submit, and register additionally checks minimum username/password length and email shape. Every invalid field is reported on one submit rather than one per round trip, each message tied to its input via `aria-invalid`/`aria-describedby` with focus moved to the first offender. A show/hide toggle reveals the typed password. | `frontend/src/components/AuthForm.tsx`, `frontend/src/lib/auth.ts`, `frontend/src/app/(app)/layout.tsx` |
| Sliding session renewal | ✅ Implemented | Active clients renew a still-valid token instead of losing work to the 30-minute expiry: `/api/auth/me` responses are cached and deduplicated, concurrent renewals share one in-flight `POST /api/auth/refresh` request (no refresh stampede), long operations (prompt delete, eval runs) pre-renew when the token would expire mid-operation, and an authenticated request that still gets a 401 retries once after a refresh. The client treats the session as expired slightly early to eliminate the post-run 401 race | `frontend/src/lib/auth.ts` (`refreshSession`, `ensureSessionValidity`), `frontend/src/lib/api.ts` (`authenticatedFetch`), `backend/app/api/auth_routes.py` |
| Legacy-account email recovery reminder | ✅ Implemented | Dismissible banner shown after login when the current user's email is null (accounts created before email was required); links to the Settings email editor. Re-checks `email` live on every mount rather than trusting only the dismiss flag, so it stops appearing the moment an email is added; dismissal itself is persisted to `localStorage`, scoped per username | `frontend/src/components/EmailReminderBanner.tsx`, `frontend/src/app/(app)/layout.tsx` |
| Session revalidation after sign-out (back/forward cache) | ✅ Implemented | The browser's bfcache can restore an authenticated page after logout without re-running mount effects; the authenticated layout re-checks the session on `pageshow` (when restored from history) and `visibilitychange`, clearing local auth state if the token is gone. Page documents are also served with `Cache-Control: no-store` (hashed `/_next/` build assets keep long-lived caching) so the Back button cannot redisplay account data post-logout | `frontend/src/app/(app)/layout.tsx`, `frontend/next.config.js` |

## Feature Detail Notes

### XML Prompt Generation
- **What it does**: Takes a list of `{name, content}` field pairs and wraps each in an uppercase XML tag — e.g. `<ROLE>content</ROLE>` — returning a structured prompt block ready to paste into an LLM.
- **User benefit**: Consistent formatting reduces trial and error; prompts are predictable and reusable.
- **Technical location**: `backend/app/services/prompt_generator.py`
- **Limitations / known gaps**: Single fixed output format (XML); no choice of output format (e.g. Markdown, JSON).

### AI Text Import (parse-text)
- **What it does**: User pastes free-form text describing their intent; the backend calls the user's connected provider with a prompt-carried JSON-schema contract to decompose the text into named prompt fields.
- **User benefit**: Eliminates the blank-page problem; users can start from rough notes.
- **Technical location**: `backend/app/services/prompt_parser.py`, `backend/app/api/routes.py`
- **Limitations / known gaps**: Runs on whatever model the user's connection specifies; there is no fallback model. Because `response_format` is not portable across OpenAI-compatible endpoints, the JSON schema travels in the prompt and the response is parsed tolerantly with one retry — a small local model can still fail both attempts, which surfaces as "try a more capable model". A missing provider connection is surfaced proactively via the capability check (see below) instead of only failing after a user attempts an import.

### Server-Side Saved Prompts
- **What it does**: Prompts with a non-null `name` are persisted in the database. The frontend loads them from `GET /api/prompts/saved` on every login, so they are accessible from any device or browser.
- **User benefit**: Named templates survive localStorage clearing, browser changes, and device switches.
- **Technical location**: `backend/app/api/routes.py` (`/saved` endpoint), `frontend/src/app/(app)/library/page.tsx`, `frontend/src/lib/api.ts`
- **Limitations / known gaps**: Folders and tags are now supported (see Prompt Organization, Versioning & Testing above). The `/saved` endpoint itself is still unpaginated (only `/history` supports `offset`) — fine at today's scale since saved prompts are a curated subset, but worth revisiting if a user's saved-template list grows large.

### Prompt History Pagination & Search
- **What it does**: `GET /api/prompts/history` takes `limit`, `offset`, and an optional `search` string; search does a case-insensitive substring match against the saved name, serialized source fields (names and content), creation date, and the visible "Unnamed generation" label.
- **User benefit**: History no longer silently truncates at a fixed cap, and users can find a specific past prompt without scrolling through everything.
- **Technical location**: `backend/app/api/routes.py`, `frontend/src/app/(app)/library/page.tsx`
- **Limitations / known gaps**: Search does not query `generated_prompt` separately or return highlighted matching snippets; it searches the source `fields` JSON used to build that prompt.
